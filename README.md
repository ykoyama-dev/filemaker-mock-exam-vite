# Claris FileMaker 技術者試験 模擬試験アプリ（Vite 版）

Claris FileMaker 技術者試験の **CFBD-1-2026（Basic Developer）** と **CFED-3-2026（Expert Developer）** の模擬試験を、ブラウザで受けられる学習用アプリです。

研修の条件に合わせて、社内推奨の技術スタック（**Vite ＋ Tailwind CSS**、入力チェックは **zod**、パッケージ管理は **pnpm**）で作り直した版です。最初に作ったフレームワークなし・ビルドなしの版は、別のリポジトリ（`filemaker-mock-exam`）にあります。

---

## 1. 何のためのアプリか

- 試験本番と同じ形式（多肢選択式・単一回答／複数回答）で、出題範囲の知識を確認するためのアプリです。
- 本番に近い問題数・制限時間で解く **本番モード** と、分野を絞って 1問ずつ答え合わせする **練習モード** があります。
- 本番モードの結果を保存し、**知識分野ごとの正答率** から苦手分野を把握できます。

### 収録している問題

| 試験 | 問題数 | 本番モード | 作成の根拠 |
|---|---|---|---|
| CFBD-1-2026 | 121問 | 40問・53分 | 学習ガイド（CFBD1G202609）の学習目標と例題の形式（71問）、Claris FileMaker ガイドブック基礎編 第3版の記載内容（50問） |
| CFED-3-2026 | 82問 | 50問・86分 | 学習ガイド（CFED3G202609）の学習目標と例題の形式 |

- すべて**オリジナル問題**です。学習ガイドの例題の文章は転記していません。
- 本番モードの分野ごとの出題数は、各学習ガイドに示された配分の目安に合わせています。
- 公式の試験問題ではありません。特に CFED-3 のエキスパート向けの細かい仕様は、Claris の公式ヘルプや実機でも確認してください。

## 2. 技術構成

| 用途 | 技術 | バージョン |
|---|---|---|
| ビルドツール・開発サーバー | Vite | 8.3 |
| 言語 | TypeScript | 6.0 |
| スタイル | Tailwind CSS（`@tailwindcss/vite` プラグイン） | 4.3 |
| 入力チェック | zod | 4.6 |
| パッケージ管理 | pnpm | 12.15 |
| 実行環境（開発時） | Node.js | 24（LTS） |

- UI フレームワークは使っていません（TypeScript で DOM を直接操作しています）。
- データベースは使っていません（研修の条件では任意）。成績はブラウザの localStorage に保存します。

### zod による入力チェック

入力チェックはすべて `src/schema.ts` に zod のスキーマとしてまとめています。エラーメッセージは日本語です（`z.config(z.locales.ja())` と個別のメッセージ）。

| 検証する対象 | タイミング | 内容 | 不正だった場合 |
|---|---|---|---|
| 問題データ（`QuestionSchema`） | 起動時 | 必須項目、OID の形式、選択肢の数、正解番号が選択肢の範囲内か、正解番号の重複、単一回答の正解が 1つか | その試験を受験できないようにし、TOP 画面にエラー内容を表示 |
| 試験の設定（`ExamSchema`） | 起動時 | ID・問題文の重複、存在しない分野の指定、配分の合計と本番の出題数の一致、各分野の問題数が配分以上あるか | 同上 |
| 保存した成績（`HistorySchema`）と出題回数（`SeenSchema`） | 読み込み時・保存前 | 日時の形式、正解数が出題数以下か、数値が正の整数か | 壊れたデータは使わずに空として扱う（画面は止まらない） |
| 練習モードの設定（`PracticeSettingsSchema`） | 開始ボタンを押したとき | 分野を 1つ以上選んでいるか、出題数が選択肢のどれか | 画面にエラーメッセージを表示し、開始しない |
| 問題一覧の絞り込み条件（`ListFilterSchema`） | 条件を変えたとき | 分野・形式・出典の値、キーワードは 100文字以内 | 画面にエラーメッセージを表示 |

## 3. 使い方

### 開発環境の準備（初回のみ）

1. Node.js 24（LTS）をインストールします。
2. pnpm をインストールします：`npm install -g pnpm`
3. 依存パッケージをインストールします：
   ```bash
   pnpm install
   ```

### コマンド

| コマンド | 内容 |
|---|---|
| `pnpm dev` | 開発サーバーを起動します。表示された URL（例：http://localhost:5173/）をブラウザで開きます。ファイルを保存すると画面にすぐ反映されます |
| `pnpm build` | 型チェック（`tsc`）をしたうえで、公開用のファイルを `dist` フォルダに出力します |
| `pnpm preview` | `dist` の内容をローカルで表示して確認します |
| `pnpm typecheck` | 型チェックだけを行います |

### アプリの操作

1. TOP 画面で、受験する試験（CFBD-1 または CFED-3）を選びます。
2. スタート画面で、モードを選んで「開始する」を押します。
   - **本番モード**：分野ごとの配分どおりに出題され、制限時間のタイマーが動きます。各分野では、出題回数が少ない問題を優先して出題します。採点結果は成績として保存されます。
   - **練習モード**：分野と問題数を選んで出題します。1問ごとに「回答する」で、正誤・解説・出典をその場で確認できます。
3. 「問題一覧を見る」では、全問題を分野・形式・出典・キーワードで絞り込みます。問題を選ぶと、その問題を表示して回答できます。
4. 「成績を見る」では、次の操作ができます。
   - 平均正答率、分野別の正答率（累計）、受験履歴の確認
   - CSV での書き出し
   - 履歴の 1件ずつの削除、またはまとめての削除

成績は使っているブラウザの中だけに保存されます。別のブラウザや別の PC とは共有されません。

## 4. 公開（Cloudflare Pages）

Cloudflare Pages で公開する場合は、GitHub と連携して次のように設定します。

| 項目 | 設定値 |
|---|---|
| フレームワーク プリセット | None（下のビルドコマンドと出力先を指定） |
| ビルド コマンド | `pnpm build` |
| ビルド出力ディレクトリ | `dist` |
| Node.js のバージョン | `.node-version`（24）で指定済み |

pnpm のバージョンは、`package.json` の `packageManager` で指定しています。

### ビルドエラー `ERR_PNPM_IGNORED_BUILDS` への対応

pnpm v10 以降では、セキュリティのため、依存パッケージのビルドスクリプト（postinstall など）が自動では実行されなくなりました。Cloudflare Pages のビルドで、esbuild や workerd のビルドスクリプトがブロックされ、`ERR_PNPM_IGNORED_BUILDS` が発生したため、リポジトリ直下の `pnpm-workspace.yaml` で実行を許可しています。

```yaml
allowBuilds:
  esbuild: true
  workerd: true
```

なお、このアプリの依存パッケージには esbuild と workerd は含まれていません（Vite 8 は rolldown を使用）。この 2つは、Cloudflare の `wrangler` を使うデプロイ工程で使われるライブラリです。同じエラーが続く場合は、Cloudflare 側のビルドコマンド・デプロイコマンドの設定も確認してください。

### Basic 認証（`functions/_middleware.ts`）

公開したサイト全体に、Basic 認証（ユーザー名とパスワードによるアクセス制限）をかけています。Cloudflare Pages Functions のミドルウェアとして、ページを表示する前に認証情報を確認します。

- Cloudflare Pages は Apache などの Web サーバーではないため、`.htaccess` や `.htpasswd`（パスワードファイル）は使いません。作成もされません。
- ユーザー名とパスワードは**コードやリポジトリには書かず**、Cloudflare の環境変数（シークレット）に保存します。

#### 設定方法

1. Cloudflare のダッシュボードで、プロジェクトの「設定」→「変数とシークレット」を開きます。
2. 次の 2つを、種類「シークレット」で追加します。本番環境に設定し、プレビュー環境を使う場合はそちらにも設定します。

   | 変数名 | 内容 |
   |---|---|
   | `BASIC_AUTH_USER` | ユーザー名 |
   | `BASIC_AUTH_PASSWORD` | パスワード |

3. 再デプロイします（環境変数の変更は、次のデプロイから反映されます）。
4. 公開ページを開き、ユーザー名とパスワードの入力画面が表示されることを確認します。

#### 動作

| 状況 | 応答 |
|---|---|
| 環境変数が未設定（空欄）、またはどちらか一方だけ設定 | 503（サイトを表示せず「設定されていません」と表示。設定漏れのまま無防備に公開されるのを防ぐため） |
| 認証情報なし・ユーザー名またはパスワードが違う・形式が不正 | 401（ブラウザに入力画面を出し直す） |
| 正しいユーザー名とパスワード | サイトを表示 |

- パスワードの比較は、比較にかかる時間から内容を推測されないよう、SHA-256 にしてから全バイトを比べています。
- 日本語や `:` を含むユーザー名・パスワードにも対応しています。

#### ローカルで Pages Functions を動かす場合

`.dev.vars.example` を `.dev.vars` という名前でコピーし、値を入れます（`.dev.vars` は `.gitignore` で Git の対象外にしています）。`pnpm dev`（Vite の開発サーバー）では Pages Functions は動かないため、Basic 認証はかかりません。

#### 注意

- 実際のユーザー名とパスワードは、コード・README・コミットメッセージに書かないでください。
- パスワードファイル（`.htpasswd`）を `public` フォルダなどに置かないでください。公開されて誰でもダウンロードできてしまいます。

## 5. リポジトリの保護（CODEOWNERS とルールセット）

`main` ブランチは、リポジトリのオーナー（`ykoyama-dev`）以外が更新できないように保護しています。

### CODEOWNERS

`.github/CODEOWNERS` で、リポジトリ内のすべてのファイルのコードオーナーを `ykoyama-dev` にしています。

```
* @ykoyama-dev
```

CODEOWNERS は「誰がレビューするか」を決める仕組みです。これだけでは更新を止められないため、次のルールセットと組み合わせています。

### ルールセット「main の保護（コードオーナーのレビュー必須）」

GitHub の「Settings」→「Rules」→「Rulesets」で設定しています。

| ルール | 内容 |
|---|---|
| プルリクエスト必須 | `main` を変更するにはプルリクエストが必要で、コードオーナー（`ykoyama-dev`）の承認が 1件必要 |
| 承認後の再確認 | 承認のあとに変更が追加された場合は、承認を取り消してもう一度承認を求める |
| 強制 push の禁止 | `main` の履歴は書き換えられない |
| 削除の禁止 | `main` ブランチは削除できない |
| 除外対象 | リポジトリ管理者のみ（オーナー自身は直接 push できる。GitHub では自分のプルリクエストを自分で承認できないため） |

他の人は、コードを見ることや、フォークからプルリクエストを出すことはできます。ただし、オーナーが承認しない限り `main` には取り込まれません。

## 6. ファイル構成

```
├── index.html            画面（TOP・スタート・出題・結果・問題一覧・成績）。Tailwind のクラスで装飾
├── vite.config.ts        Vite の設定（Tailwind CSS プラグイン）
├── package.json          スクリプトと依存パッケージ（pnpm で管理）
├── pnpm-lock.yaml        依存パッケージのバージョン固定
├── pnpm-workspace.yaml   pnpm の設定（esbuild / workerd のビルドスクリプトを許可）
├── .github/CODEOWNERS    コードオーナーの設定（すべてのファイルのオーナーを ykoyama-dev に指定）
├── .node-version         Node.js のバージョン（Cloudflare Pages 用）
├── .dev.vars.example     Basic 認証の環境変数のひな形（値は空欄）
├── functions/
│   └── _middleware.ts    Basic 認証（Cloudflare Pages Functions のミドルウェア）
├── public/favicon.svg
└── src/
    ├── main.ts           画面の動作（出題・採点・一覧・成績の保存と集計・CSV 書き出し）
    ├── schema.ts         zod のスキーマ（入力チェックの定義）
    ├── storage.ts        localStorage への保存・読み込み（読み込み時に zod で検証）
    ├── dom.ts            DOM 操作のヘルパー
    ├── style.css         Tailwind CSS の読み込みと共通部品（ボタン・カード・選択肢など）
    └── data/
        ├── exams.ts            試験ごとの設定と、起動時の zod 検証
        ├── help.ts             参考リンクのベース URL
        ├── cfbd1-base.ts       CFBD-1 の問題（学習ガイド準拠 71問）
        ├── cfbd1-guidebook.ts  CFBD-1 の問題（ガイドブック基礎編準拠 50問）
        └── cfed3.ts            CFED-3 の問題（82問）
```

### 問題を追加・修正するとき

`src/data/` の各ファイルに、次の形式で書きます。形式が正しくないと、起動時に zod のエラーが TOP 画面に表示されます。

```ts
{
  id: "1-01",              // 一意の ID
  field: 1,                // 知識分野の番号
  oid: "FM26-1.1.2",       // 学習目標の OID
  type: "single",          // "single" = 単一回答 / "multi" = 複数回答
  q: "問題文",
  choices: ["選択肢A", "選択肢B", "選択肢C", "選択肢D"],
  answer: [2],             // 正解の選択肢番号（0 始まり）
  explain: "解説",
  src: "ガイドブック基礎編 6.3.2",   // 出典（任意）
  ref: "https://help.claris.com/...", // 参考リンク（任意・https のみ）
}
```

## 7. AI にどう頼んだか

このアプリは、VS Code 上の **Claude Code**（Anthropic の AI コーディングアシスタント）に日本語で依頼して作成しました。

### 最初の版（filemaker-mock-exam）を作るまで

| # | 依頼した内容 | AI が行ったこと |
|---|---|---|
| 1 | 試験資料（学習ガイド・学習目標一覧の PDF）を**要約して**ほしい | PDF を読み込み、試験の概要・出題配分・学習目標・例題の傾向を要約した |

### 依頼するときに気を付けたこと

- **研修の条件をそのまま伝えた**：「Vite ＋ Tailwind CSS」「zod」「pnpm」「データベースは任意」など、指定された条件を原文のまま伝えた。
- **すぐに作らせず、まず意味と影響を確認した**：「理解できるか」「なぜ必要か」と質問し、作り直しの範囲や必要な準備を説明させてから着手した。
- **AI の確認事項に回答してから進めた**：TypeScript を使うか、UI フレームワーク、バージョン、インストールの可否、リポジトリの分け方を、AI の質問に答える形で決めた。
- **動作確認の結果を報告させた**：AI がブラウザを自動操作してテストし、zod の検証（壊れた保存データ、分野の未選択など）を含めて結果を報告させた。
